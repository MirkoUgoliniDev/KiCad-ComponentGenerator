# Windows package (MSI)

How KiCadGen becomes `KiCadGen-X.Y.Z.msi`, and what the installed program
does differently from `python main.py`. Modelled on the employee-scheduling
project (WiX 3.14, same dialogs, same release flow); the executable is built
with PyInstaller instead of jpackage.

## 1. What is produced

| Output | Built by | Content |
|---|---|---|
| `dist\KiCadGen\` | PyInstaller (`packaging\KiCadGen.spec`) | `KiCadGen.exe` and `_internal\` (Python, Qt, VTK, OpenCV, onnxruntime, program files) |
| `dist\KiCadGen-X.Y.Z.msi` | WiX 3.14 (`packaging\KiCadGen.wxs`) | installer for all users, in `C:\Program Files\KiCadGen` |

The MSI: welcome, license, folder choice, install, «Launch KiCadGen»;
Start menu and desktop shortcuts; uninstall from Settings > Apps. A newer
version replaces the installed one (fixed `UpgradeCode`
`E97182CB-C126-4B0C-B336-172FE2830FB7` — **never change it**), and so does a
rebuilt MSI of the **same** version (`AllowSameVersionUpgrades="yes"`: with
`Product Id="*"` every build is a new product, and refusing same-version
upgrades would install it side by side); an older version is refused. light
suppresses ICE61, the warning that this choice raises. A custom install folder
is remembered in `HKLM\Software\KiCadGen\InstallFolder` and proposed again by
the next upgrade (from the first version that writes it). «Launch KiCadGen»
starts the program from the folder actually chosen. On the last page the
installer says which of FreeCAD and KiCad it **may not** have found: it looks
for `freecadcmd.exe` and `kicad-cli.exe` in Program Files and Program Files
(x86), as the program does, but it cannot see PATH or the `FREECAD_CMD_PATH`
and `KICAD_CLI_PATH` overrides that the program also honours.

## 2. Build

Requirements on the building machine: Windows x64, Python 3.13 from python.org
(found automatically, or set `KICADGEN_BUILD_PYTHON` to its `python.exe`).
WiX 3.14 is taken from `C:\tools\wix314` or Program Files. When it is missing
it is downloaded (39 MB) **only if** the maintainer provides the SHA-256 of
`wix314-binaries.zip`, copied from the official release page
(https://github.com/wixtoolset/wix3/releases/tag/wix3141rtm), with
`build-msi.ps1 -WixSha256 <hash>` or the `KICADGEN_WIX_SHA256` variable (in
GitHub Actions: the repository variable `WIX314_SHA256`). Without it, or when
the hash differs, the build stops: the hash is not written in the scripts
because it has not been verified yet.

```powershell
.\scripts\build-windows.ps1                   # executable + MSI
.\scripts\build-windows.ps1 -Package app-image # executable only
```

The script:

1. creates `.venv-build` (never the development `.venv`; recreated when it
   is not Python 3.13) from `requirements-build.txt`, with the exact versions
   of `requirements-release-constraints.txt` (`pip -c`; the release workflow
   uses the same file);
2. **generates** the initial profile database from the code with
   `tools\make_seed_db.py` (a fresh `ProfileStore` on an empty path) and
   verifies it: defaults equal to `analysis_profiles.factory_defaults()`, no
   metadata carrying a local path (`legacy_backup` empty). Neither the local
   `data\analysis_profiles.sqlite3` (the developer's own profiles) nor the one
   in git (stale default prompts, the developer's `legacy_backup` path) is
   ever shipped;
3. collects the license files of the build environment and of CPython with
   `tools\collect_licenses.py` into `build\licenses`, shipped as
   `_internal\licenses` (with `MANIFEST.txt`; no network);
4. renders `packaging\KiCadGen.ico` from `kicadgen\gui\assets\app-icon.svg`;
5. runs PyInstaller;
6. checks the result with `KiCadGen.exe --check-runtime`: the libraries, the
   GUI module (`kicadgen.gui.main_window`) and the required resources
   (`LICENSE`, `THIRD_PARTY_NOTICES.md`, the seed database, the FreeCAD
   scripts, the icon, `licenses\MANIFEST.txt`) must all be there; no window,
   no `.env`, no AI call;
7. builds the MSI (`scripts\build-msi.ps1`: heat, candle, light), with the
   banner, dialog image and license generated by `tools\make_installer_assets.py`.

The script returns to the caller's folder when it ends, also on failure.

### YOLO weights: not shipped

`models\pcb_yolov8s.onnx` is **not** in the package by default: its license
is ambiguous (MIT model card, AGPL metadata; see `docs\yolo-photo-workflow.md`).
`-IncludeYoloModel` ships it; use it only once redistribution is allowed.
Without the weights the program works; the local detector asks for an
`.onnx` file in the «YOLO model» field.

## 3. Release

```powershell
.\scripts\publish-release.ps1 -Version 1.0.1
```

Sets `kicadgen.__version__`, commits, tags `v1.0.1` and pushes. The tag
starts `.github\workflows\release.yml`. Its `build` job (`windows-latest`,
read-only token, no persisted Git credentials) checks that the tag matches the
version, runs the tests, builds the MSI and uploads it as an artifact; the
`publish` job, the only one with write access, runs no project code: it
downloads the artifact and creates the GitHub Release. The tag reaches the
scripts only through the `TAG` environment variable. The actions still use
major tags: pinning them to commit SHAs is a TODO in the workflow. By the
user's choice the release is made from the current branch.

## 4. Installed program versus sources

| | `python main.py` | Installed |
|---|---|---|
| Program files | repository | `C:\Program Files\KiCadGen` (read-only) |
| `config.json`, databases, model cache, `.env` | repository | `%LOCALAPPDATA%\KiCadGen` |
| Projects (default workspace) | `generated\` | `Documents\KiCadGen` |
| Profile database | `data\` | copied from the package at first start |

All of it is decided in one place, `kicadgen\app_paths.py`.
`KICADGEN_DATA_DIR` moves what is resolved through `app_paths`
(`user_data_dir`, `data_file`, `env_files`, and the projects to
`<dir>\generated`); set it before starting the program. The variables used by
the tests (`KICADGEN_CONFIG_PATH`, `KICADGEN_PROFILE_DB`, `KICADGEN_MATCH_DB`,
`KICADGEN_YOLO_MODEL`) still win. Uninstalling never removes the user's data.

The profile database is copied from the package atomically (temporary file,
then rename). If the user's copy is not a valid SQLite database (for example
truncated by a crash during the first copy), it is renamed
`analysis_profiles.sqlite3.corrupt-<date>-<time>` — never deleted — and a
fresh copy is made. A locked or busy database is never treated as damaged.

## 5. Checks before publishing

- `pytest` (includes `tests\test_packaging.py`: version format, fixed
  UpgradeCode, shipped resources, weights opt-in, seed generated from code,
  license collection, workflow permissions, WiX download verification,
  PowerShell syntax, icon).
- The build's own `--check-runtime`.
- **Install test in a virtual machine or Windows Sandbox, never on the
  development machine**: install, open a project, generate a component with
  FreeCAD installed, install a newer MSI over it, uninstall and check that
  `%LOCALAPPDATA%\KiCadGen` and `Documents\KiCadGen` are still there.

## 6. Known limits

- No digital signature: Windows SmartScreen shows «unknown publisher». A
  code-signing certificate is needed to remove the warning.
- About 200 MB: Qt, VTK and OpenCV are most of it.
- FreeCAD and KiCad are separate programs with their own licenses: they are
  detected, never bundled.
- `.pt` YOLO models (PyTorch) are not supported by the installed program:
  PyTorch and Ultralytics are excluded from the package (size, license).
  Use an `.onnx` export.
- The OpenRouter API key has no input dialog yet: it goes in
  `%LOCALAPPDATA%\KiCadGen\.env` (see `INSTALLATION-WINDOWS.md`).
- ICE60 warnings from light (language of library files) are expected; ICE61
  is suppressed on purpose (same-version upgrades).
- The shortcut components use HKCU key paths (ICE38/ICE43). The marker values
  under `HKCU\Software\KiCadGen` may remain in the hive of the administrator
  who installed, when another account uninstalls; they are harmless.
