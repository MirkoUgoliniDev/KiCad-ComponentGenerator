1. What KiCadGen does

KiCadGen creates a component for KiCad from technical documents and photographs: the footprint (.kicad_mod), the electrical symbol (.kicad_sym) and the STEP model (.step). The documents are read by an artificial intelligence model (through OpenRouter or the direct DeepSeek API); the program then turns what the model has read into geometry, with deterministic rules.

For a board with components mounted on it (a module, a development board) KiCadGen reconstructs the mechanical envelopes: position, size and orientation of the bodies visible in the photo. It does not do reverse engineering: the bodies are generic volumes, or STEP models from the KiCad library chosen because their dimensions are similar.

2. Before you start

  • FreeCAD (freecad.org) builds the STEP models. Without FreeCAD you still get the footprint; the progress window says which steps cannot be run and why.
  • KiCad (kicad.org) is needed to test the result and to install the libraries.
  • API key: the document analysis is paid and requires a key from one of the two supported providers, OpenRouter (one key for many vendors; the default model of the installed program, anthropic/claude-opus-5, goes through it) or DeepSeek (direct API) (models deepseek-api/...; when running from source the default is deepseek-api/deepseek-flash). The model is chosen from the interface: Configuration → General AI defaults..., Model tab, or the AI model panel for the session. The key is entered from Configuration → AI account...: the window lists every provider with the source of the key in use (environment variable, Credential Manager, .env file or none) and the current balance; choose the provider, paste the key, press Verify (no call to a model, no cost) and then Save; it is kept in the Windows Credential Manager (KiCadGen/OpenRouter, KiCadGen/DeepSeek). Remove key deletes only that entry. The .env file in the folder %LOCALAPPDATA%\KiCadGen (lines OPENROUTER_API_KEY=sk-or-... and/or DEEPSEEK_API_KEY=...) remains valid; a key saved with «AI account...» takes precedence over the one in the file. If the key is missing, the program says so before starting an analysis and offers to open the window. When the key works, the AI credit line of the Project tab shows the balance of the provider of the chosen model.

The interface language (Italian, English, French, German) is chosen from the list above the tabs.

3. Creating the project

A project is a folder: its name is also the name of the footprint and of the STEP model.

  1. Menu File → New project... (Ctrl+N). Type the name, for example RS485_TTL, and confirm.
  2. The folder is created in the Workspace shown in the Project tab (in the installed program, Documents\KiCadGen by default). The folder button next to the field lets you choose another one.
  3. To resume a job: File → Open project... (Ctrl+O) lists the projects of the workspace, most recent first. File → Rename project... (F2) changes the name of the folder and, together with it, that of the footprint, symbol and STEP model. Without an open project the window shows the start page, with the two commands and the recent projects, which reopen with one click.

4. Loading the documents

The Project tab guides the preparation in two steps: Documents and Mounting and analysis. Use Continue and Back to move between them: these buttons do not start the analysis. In the first step, Back to projects saves the project and returns to the screen with New, Open and recent projects. Name and workspace are in the collapsible Project details panel, above the documents.

In the Project tab, the documentation panel has a card for every loaded file. For each file you tick all the roles it contains: a PDF datasheet, for example, is often pinout, dimensions and recommended lands at once: this is why a PDF is always a «Datasheet», receives that role alone and the other boxes cannot be ticked. Declaring the roles tells the model how to use each file:

RoleWhat it contains
Pinout The numbering and position of the contacts. The program does not assume it is seen from above: the model says from which side the drawing is seen and the mirroring is done by the code.
Dimensions The dimensioned drawing seen from above: length and width of the body, position of the holes, distances between the rows of contacts.
High resolution A real photograph of the part, from above: it is used to locate the mounted components. Only the files ticked as photos go to component recognition and calibration; they must be images, not PDFs.
Land pattern The lands recommended by the manufacturer (in datasheets, the «land pattern»): shape and position of the lands and holes.
Side view The heights: of the body, of the components, the thickness of the board.
Datasheet The manufacturer's complete datasheet, PDF or images: the AI looks in it for pinout, dimensions, lands and side view and reports the sections that are missing. It is not a photo: it is not used to recognise the mounted components.
  • Add…, in the New document card, copies the file into the project's docs folder (the original is not touched). Formats: PDF, PNG, JPG, WEBP, GIF. Then tick its roles: a file without roles blocks the analysis until you choose one or remove it.
  • On the card of each file: the folder replaces the file keeping its roles, the eye opens the preview with zoom, the bin removes the local copy, which stays recoverable in docs/.history.
  • A role that no file has is simply «not provided»: the model knows it and does not replace it with other files.
Photos from above are calibrated on the board dimensions. You need a photo taken from above, nearly aligned, with the length of the board horizontal and the board outline distinguishable from the background (of any colour). The program does not correct perspective: a tilted photo is rejected, and the role card reports it.

5. Choosing the component type

In the Mounting and analysis step of the Project tab, Component type tells the model what it is reading, and therefore which dimensions to look for.

TypeWhat happens
Single through-hole component (THT) Pads with a hole, dimensions from the datasheet's recommended layout.
Single SMD component No hole, sizes from the recommended lands.
Board with components · through-hole connectors Besides the footprint, the photo inventory starts: the bodies mounted on the board are searched for on the photo, measured and turned into 3D volumes, which are then reviewed and corrected.
Board with components · castellated connectors (half-holes)

For single components the photo inventory is not run: no body detector, no body review, no pause after the inventory.

The AI tools panel is closed at first: the summary shows the active detector and model. Open it with the arrow to see or change the other choices:

  • Photo detection (only matters for boards): YOLO + local SMD network (v3) (the default when running the program from source: the detector proposes the boxes, a local network classifies the kept bodies and only those it cannot resolve go to the AI; in the installed Windows program the entry is disabled because PyTorch is not included, and the default is the next entry), Local YOLO + AI verification (the detector on your computer proposes the boxes, the AI model verifies them), AI (current), Vision model only (no local detector), or Local YOLO only (pretest, no AI), which shows only the boxes found by the detector without any paid call. The local detector requires a YOLO model file, chosen in the YOLO model row: .onnx (.pt files only work when running the program from source). The button next to it opens Choose the YOLO model: for every model in the folder it shows format, size, origin, licence, training data, recognised classes and compatibility. A .pt file runs code when it is loaded, so it is checked only when you press Check compatibility. If the file is missing or not compatible, the analysis stops before spending anything.
  • AI model: the single model used for documents, photos and verification. The button next to it chooses a different model (filterable by cost, OpenRouter or DeepSeek source) for this session only; the default and its source are set from Configuration → General AI defaults..., the prompts per type from Configuration → Manage AI types and profiles....

6. Starting the analysis and checking the costs

  1. Press Extract parameters with AI. It is a paid analysis: it uses credit of the provider of the chosen model. Before starting, the log writes which models will be used.
  2. A window shows the progress: the list of phases and who works in each one (AI model, Crop reading and Marking reading are the paid remote phases; YOLO, Local SMD network, OpenCV, KiCadGen, the KiCad library and FreeCAD work on your computer). Stop stops the work: a request already sent must finish, but no further ones start.
  3. At the end, the cost of the last analysis appears in the window and in the AI log (icon at the top of the Project tab). If the answer was taken from the local cache, there was no paid call and the log says so.
  4. The AI credit line shows the balance of the provider's account and the total project cost, the sum of all the paid calls made for that project, split by provider and saved in ai-costs.json in the project folder (OpenRouter reports the cost of every call; DeepSeek does not, so it is computed as tokens × official price).
Every command that spends money says so in its tooltip (the text that appears when you hold the mouse over the button). The review and 3D regeneration commands are free.

7. Reviewing the bodies found on the photo

Only for the two Board with components types.

The review takes place in a single window, in two stages: first on the local detector's proposals, then on the bodies reconciled with the AI. Both stages are free.

Stage 1: the local detector's proposals

With a YOLO detector, before any paid call the review window opens with the boxes found on your computer. Remove those that fall on lettering, holes or empty lands, draw the missing ones, then OK passes the kept boxes on. If you cancel, the analysis stops without paying anything. The kept proposals are saved in the project's photo-review folder. With Local YOLO only (pretest, no AI) the work ends here.

Stage 2: pause after the inventory

When the AI inventory is finished, the same window reopens with the reconciled bodies, before the choice of models and the 3D generation. Beside the AI's reading, the detector's reading stays (class, confidence, box), never overwritten: if the detector's original box differs from the current one, it appears as a dashed ghost under the chosen body. The bodies proposed by the AI alone (dashed yellow) start excluded: you keep them with Keep or leave (T). The pause is turned on or off from Configuration → Generation options... (Stop after the AI inventory to review the bodies (free)); when it is off, the work continues with the bodies as the AI proposed them.

The window's commands

The window shows the photo with a rectangle for each body:

  • Add component (R): draw a rectangle on the photo, then assign the type. Delete selected (Del) removes the chosen body; Lasso (L) selects together the boxes enclosed in a rectangle.
  • Copy format: click the component to copy, then click the others to paste size, height, type, package and KiCad model (position and rotation stay).
  • Zoom with +, - or the mouse wheel; Fit photo (F) shows the whole photo; the photo button (P) shows it whole, dimmed or hidden to read the outlines alone.
  • With a body chosen in the list or on the photo, Parameters… opens Component parameters: three read-only sections (what the local detector read, what the AI read with type, package and marking and their confidences, the outcome of the two crop readings and the SMD network outcome row; the state of the KiCad model with Choose KiCad model…, see chapter 11, also by double-clicking in the list) and below them the editable corrections: name, type, marking, dimensions, rotation, height. Centre and sides can also be corrected by dragging the rectangle and its handles on the photo; the rotation is changed only with the numeric Rotation field. No AI request.
  • The list markers: [!] means the row has at least one warning (usually «KiCad model not confirmed»), [?] that the type has not been established; another marker reports that the detector's class contradicts the AI's. The doubts button shows the uncertainties declared by the model, as text.
  • Apply corrections saves; Cancel leaves everything as it was. After applying them, Regenerate STEP model with these annotations in the STEP model tab rebuilds the STEP.

Later, from the Project tab:

  • Component review… reopens the stage saved in the project: the detector's proposals before the AI inventory, the reconciled bodies with dimensions and choice of KiCad models after it. Free.
  • Rerun AI inventory (paid)… redoes only the AI inventory on the saved proposals. It is the only one of the two that spends.

8. Generation: footprint and STEP model

When the analysis is valid, the generation starts by itself. In the same progress window of chapter 6, after the analysis phases, the generation takes four steps, and for each one the heading says who runs it:

  1. 2D footprint (KiCadGen): the .kicad_mod file, written by the program.
  2. Compare with accepted matches: for boards, the bodies are compared with the body/model matches already accepted (Accepted matches archive…).
  3. Models from the KiCad library: for every body the models of the KiCad 3D library with compatible dimensions are searched for.
  4. 3D solid with FreeCAD: the .step file.

When a step cannot be run (for example FreeCAD not installed) the window says why. A 3D error does not cancel the footprint already written.

When the generation succeeds the window stays open with all the steps ticked and the state «Completed»: close it with Close. In case of error or interruption it closes by itself and the error is shown.

The Footprint preview tab shows the 2D drawing to scale with the dimensions, the pin numbers and the Grid (step 1 mm or 0.1 in, with a dotted sub-grid for drawings); the table icon opens the pinout. The preview is a draft, like the symbol: the Reference and Value texts can be dragged, drawings are added from the palette, the host lands can be edited, with Undo edit / Redo edit. Apply writes the .kicad_mod file, Cancel discards the changes not applied, Recover draft restores a draft not applied after an unexpected shutdown. The commands of the KiCad tab use the applied file: a draft not applied is not installed and is reported by Check component for KiCad.

For boards, the Host-board footprint panel lets you choose the mounting directly from the preview, without going back to the beginning or repeating the analysis:

  • Direct soldering / module lands keeps the geometry of the module's lands, including the castellated contacts.
  • Pin headers / circular through-hole pads uses through holes for the connectors. Set Pad Ø: and Drill Ø: in millimetres. The hole must be smaller than the pad; diameters incompatible with the distance between contacts are reported. In matrix footprints pad 1 stays square so that it can be recognised.

The preview changes immediately. To write the file, press the refresh icon with the tooltip Update footprint only: it needs data already acquired or an existing footprint. This action does not call the AI and does not regenerate the STEP model. The choices are kept in sync with those of the Mounting and analysis step.

The mounting concerns the footprint on the host board: the physical geometry of the 3D module, derived from the photo, stays unchanged. A castellated contact that has only a half-hole is not turned into a through hole.

9. The «Electrical symbol» tab

Between «Footprint preview» and «STEP model» you find the symbol to use in the schematic. The numbers are those of the footprint's electrical pads and cannot be changed in this table. You can correct the function, choose the electrical type and move the pins freely in the editor.

Drag the terminal, the number or the name of a pin to move it freely, even far from the rectangle. The connection point stays snapped to the 0.1 in (2.54 mm) grid, even when hidden. The move keeps the orientation. On an occupied position, the two pins swap places keeping number, name, type and orientation.

With a right click on the pin you can rotate it by 90 degrees clockwise or anticlockwise, or by 180 degrees. The connection point stays still. The eight green handles resize the rectangle around its centre without moving the pins.

The single bar above the editor uses icons with tooltips. In narrow windows, the commands that do not fit are available in the bar's overflow menu. Select a pin: the arrows move it by one grid step, R rotates it clockwise and Shift+R anticlockwise, with the focus on the view. The Pin position and orientation command, in the bar, lets you enter X, Y and angle. The coordinates snap to the grid; a connection point that is already occupied is refused.

Multiple selection: Ctrl+click adds or removes a pin; Shift+drag selects the terminals enclosed in the rectangle. Ctrl+Shift adds the area to the current selection. The selection icon lets you use the rectangle without holding Shift; turn it off to go back to dragging pins. Drag a selected pin to move the group. Group rotations take place around the active pin. A collision with other terminals cancels the whole operation.

Align and distribute aligns X or Y to the active pin. Distribution requires at least three pins, keeps the first one and uses a regular step that is a multiple of the grid: the last one may move to respect it. The padlock locks the rectangle's handles without locking the pins. Below the view you can see the cursor coordinates, the zoom and the active pin.

Check symbol reports missing names, overlapping texts in the preview and passive/unspecified types still to be verified. The same check precedes the export; you can cancel or choose Export anyway. Changing a type in the table records it as verified.

Recover draft: finished edits are saved in a separate recovery file in the project folder. After an unexpected shutdown, reopening the same project shows that a draft is available: press the Recover draft icon. The recovery does not replace the saved project until you press Apply. A draft from another revision of the project is not restored automatically. Cancel discards the recovered draft; a successful Apply deletes the recovery file.

Undo edit / Redo edit manage the history of the edits. With the focus on the editor, Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y also work. Esc cancels the drag in progress. Reset layout goes back to the two initial columns keeping names and electrical types. Hold the left button down on empty space and drag to move the view without changing the symbol. The wheel zooms around the cursor; use Fit to see everything.

Apply saves names, types, positions and sizes in the project. The names also update the 2D and 3D labels. Cancel discards the changes not applied. The Undo/Redo history stays available after Apply. If saving fails, the draft stays available to try again. Before closing or changing project, apply or cancel the changes to the symbol. No new AI analysis or FreeCAD generation is needed.

The initial types are passive: they do not attest the electrical behaviour of the circuit. Check on the datasheet whether input, output, bidirectional, power_in or other types are needed before using KiCad's electrical checks. Equal names such as GND can belong to different numbers; numbers that are duplicated or absent from the footprint prevent the export.

Export KiCad symbol saves a .kicad_sym library. Add it in KiCad to the symbol libraries. The reference to the footprint is KiCadGen:nome_componente: use the same library name when you install the footprint, or change the association in KiCad. The installation from the «KiCad» tab still handles footprint and STEP model; the symbol library is exported separately.

Shortcuts: Ctrl+3 opens the symbol, Ctrl+4 the STEP model, Ctrl+5 KiCad.

Electrical types suggested by the AI

In the Electrical symbol tab, Suggest pin types with AI uses the documents declared as pinout or datasheet and the configured AI model. Before the call the model and the documents are shown; the analysis may incur costs. The proposals include source and reasoning: check them and select the ones to use. Uncertain cases stay to be verified; types already confirmed are not preselected. The changes enter the draft as a single undoable operation and are saved with Apply.

The AI analysis can be cancelled: a request already sent must finish, but no further attempts are made and the answer is discarded. Renaming a pin revokes the confirmation of its previous type. To confirm a type already shown, select it again in the table's menu.

10. The «STEP model» tab

The model is rotated with the mouse; the navigation cube goes to the standard views. In the bar at the top:

  • Pin numbers: they appear only when looking at the part from the pin side (bottom view). Looking from below you find the datasheet's bottom view again: it is a practical check of the mirroring.
  • Pinout table, Fit, and opening the 3dshapes folder with the STEP files.
  • Edit components… (with Ctrl+E, or right click on the body in the 3D view and Edit component...; it no longer has an icon in the bar): name, type, position, dimensions, rotation, colour and marking of every body, by hand. It also works without the photo. After Apply the STEP model is regenerated with FreeCAD. No AI request.
  • Regenerate STEP model with these annotations: rebuilds the STEP from the current bodies, including the corrections just applied. Free.
  • I like it — remember these models…: saves the matches between bodies and KiCad models, which will be proposed straight away on a future board (to be confirmed). The archive is reviewed with Accepted matches archive….
  • Copy format: as in the review, copies size, type, package and KiCad model from one body to the others.
  • For castellated modules, a drop-down list corrects the contact type of all the sides.

The 3D viewer is loaded the first time the tab is opened: until it is ready, the tab shows a placeholder and nothing is lost.

With a right click on a body of the model: Remove from the STEP model (false positive) (and Put back into the STEP model), Rotate the solid, Edit component... and Change KiCad model....

11. Choosing the STEP model of a component

The STEP model choice window opens from Choose KiCad model… in the review or from Change KiCad model... in the 3D view. It shows up to five candidates from the KiCad library, with their dimensions, beside the crop of the photo of the component.

  • The candidate's preview is oriented as it will be mounted on the board. The rotation is set by hand, or with Automatic: infer the CAD axes from the outline.
  • The Colours tick box shows the preview with the colours of the STEP file; when off, the preview is a single colour and is faster. The choice is remembered.

12. Male pins under the board

For the two Board with components types, the Show headers in the STEP model tick box in the Mounting and analysis step of the Project tab or in the bar of the STEP model tab adds under the board the male strips with square pins, like a board with the strips already soldered. On castellated boards they are placed only on the contacts with a through hole.

It is a choice separate from the mounting of the footprint on the host board. It changes neither the analysis nor the footprint: after changing it you just regenerate the STEP model with the icon next to the tick box. The two tick boxes stay in sync. The module body, with copper and holes derived from the photo, does not change with the chosen mounting type.

When you change only this tick box, the regeneration reuses the models of the components chosen in the last successful generation: it skips the comparison with the accepted matches and the search in the KiCad library. What remains is building and saving the solid with FreeCAD. The reuse is prepared by the first complete generation with this version; if dimensions, components, annotations or model files also change, the complete procedure is run again.

13. The «KiCad» tab: testing and installation

The Files ready for KiCad panel lists footprint, electrical symbol and STEP model with their state. The isolated test and the two installations are blocked until the files on disk match the parameters of the project, and each block names its remedy, enabled right beside it: Apply to files (metadata or footprint not yet written), Update the symbol file (the exported .kicad_sym does not match the applied symbol), Remove the obsolete STEP model (an old STEP that cannot be rebuilt). When the STEP was built on different lands, or only colours or annotations have changed, the remedy is the regeneration button in the bar of the «STEP model» tab (tooltip Regenerate STEP model with these annotations). A project saved by an earlier version may require an Apply to files. The commands are also blocked while a background job is running. They use the applied files: a draft of the footprint or symbol that has not been applied does not block the commands, is not installed and is reported by Check component for KiCad.

The collapsible Component metadata panel contains reference designator (letters only: KiCad adds the number; the proposal in grey counts as filled), description, keywords, datasheet (URL or file) and footprint filters. Designator, description, keywords and datasheet are required: without them, installation is blocked and the commands' tooltip says which fields are missing. The KiCad checks (KLC) list updates while you type (⛔ error, ⚠ warning) and Apply to files writes the values into the footprint and the symbol; a ⛔ error makes the application be refused.

In Review before installation there are three icons: Quick guide to using the component in KiCad (a five-page procedure: install, place the footprint, export and register the symbol, link them, update the PCB), Check component for KiCad (see below) and Test in KiCad.... In Library installation the two installations.

CommandWhat it does
Test in KiCad... Creates a small temporary project with the footprint and the STEP model, in the component's .kicad-preview subfolder, and opens it in the PCB Editor. In KiCad press Alt+3 for the 3D view. It does not install and does not change any KiCad library.
Install in KiCad project... The recommended choice. Choose the folder of a KiCad project: KiCadGen.pretty and KiCadGen.3dshapes are created and the library is registered in the project's table with relative paths (${KIPRJMOD}), so the project stays portable.
Install as global library... Makes the footprint available in all the projects of this computer. It requires KiCad to be installed (the user's global table is found with kicad-cli); choose the libraries folder and the library is registered in KiCad's global fp-lib-table with absolute paths. The other libraries of the table stay as they are. If KiCad has never been started that table does not exist yet and the installation is refused: start KiCad once, complete the initial library setup and try again.

Before overwriting a component already installed, or moving a KiCadGen library already registered elsewhere, the program asks for confirmation. Before changing a table it keeps a .kicadgen-backup copy of it and, if a step fails, it puts back everything it had touched. The symbol is not registered in any table: it is exported with Export KiCad symbol… (also from the symbol row of this tab) and added in KiCad with Manage Symbol Libraries. Open component folder opens the folder with footprint, STEP model and documents. The Exports tab (Ctrl+6) keeps the history of the installations and symbol exports made from this computer.

Checking the component

In the KiCad tab, the Check component for KiCad icon checks the generated files, the match of the pin-pad numbers and, if kicad-cli is available, tries reading footprint, symbol and STEP with KiCad CLI, using a temporary folder (without it, that test is reported as not run). The copyable report distinguishes passed checks, errors, warnings and checks not run. The applied symbol is tested even if not yet exported; drafts not applied are excluded and reported. This check does not certify pinout, dimensions, visual 3D alignment or installed libraries; ERC and DRC must be run on the final schematic and board.

The check stays available when the footprint exists but the STEP is missing; installation stays disabled until the required files are present. The original 3D references and transformations are checked separately from the normalised temporary copy. Relative paths or KiCad variables that are not resolved need checking in the destination project.

14. Where the logs are

FileWhereContent
analisi-ai.logIn the project folder The analysis diary, written line by line as the work proceeds: steps, models used, costs, warnings. It can also be read from the program with the AI log icon.
freecad.logIn the project folder FreeCAD's output during the construction of the STEP model.
crash-reportslogs folder of the program data (installed: %LOCALAPPDATA%\KiCadGen\logs) One file for every unexpected error of the program, with version, system and error trace. Only the 20 most recent are kept.

The Help → Open log folder menu opens the folder of the open project, where analisi-ai.log and freecad.log are; without an open project it opens the logs folder of the program data.

15. Reporting a problem and updates

  • Help → Report a problem opens in the browser a new issue on the project's GitHub repository, already filled in with the version of KiCadGen, the operating system and whether FreeCAD and KiCad are present. The program also opens the log folder: attach the useful files yourself, after looking at them, because they may contain the names of your folders and projects. The issue on GitHub is public and is not sent until you submit it.
  • Help → Check for updates... compares this version with the latest one published on GitHub. The check takes place only when you ask for it.

The project: github.com/MirkoUgoliniDev/KiCad-ComponentGenerator.

16. Limits to be aware of

  • The AI analysis can make mistakes: always check footprint and STEP model in the previews before using them.
  • The body heights derived from a single photo from above are estimates, not measurements. Verify heights and critical distances with dimensioned drawings or with a measurement.
  • The photo inventory does not guarantee that all the bodies have been found: this is why the review and Edit components… exist.
